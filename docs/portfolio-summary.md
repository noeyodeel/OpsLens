# OpsLens Portfolio Summary

## 한 줄 소개

HIS/ESB 인터페이스 운영 오류 로그를 문서 기반으로 분석하고 처리 이력을 축적하는 AI 운영 지원 대시보드입니다.

## 만든 이유

실제 운영 업무에서는 오류 로그 테이블을 매일 확인하고, 프로시저명과 오류코드를 기준으로 관련 정의서, 대상 컬럼, 원천 데이터, 이전 처리 이력을 찾아야 합니다.

이 과정은 반복적이고 수작업 비중이 높기 때문에 다음 흐름을 자동화하는 방향으로 프로젝트를 설계했습니다.

```text
오류 로그 확인
  -> 관련 문서 검색
  -> 원인 후보 분석
  -> 확인 SQL 제안
  -> 처리 상태/메모 저장
  -> 유사 오류 이력 재사용
```

## 핵심 기능

- 운영 오류 로그 대시보드
- Oracle 오류코드별 원인 후보와 확인 항목 제공
- 로컬 문서 폴더 기반 인터페이스 정의서 자동 매칭
- Excel/PDF 내용 일부 추출 후 분석 context 구성
- OpenAI API 연동 구조
- API 키가 없을 때 mock RAG 분석 fallback
- 처리 상태와 운영 메모 저장
- 유사 오류 처리 이력 표시

## 기술 포인트

- Spring Boot API로 분석, 문서 매칭, 처리 이력 관리 구현
- React/TypeScript로 운영 대시보드 구현
- Apache POI로 Excel 인터페이스 정의서 일부 파싱
- Apache PDFBox로 운영 매뉴얼 텍스트 일부 파싱
- OpenAI Responses API 호출 구조 구성
- 실제 운영 DB 대신 mock 데이터로 민감정보 없이 시연 가능하게 구성
- 운영 문서는 `docs/knowledge-local`에 로컬 보관하고 Git 제외

## 이력서용 문장

### 짧은 버전

HIS/ESB 인터페이스 오류 로그를 대상으로 문서 기반 AI 분석과 처리 이력 관리를 제공하는 운영 지원 대시보드를 구현했습니다.

### 상세 버전

운영 중 반복 발생하는 Oracle 오류 로그를 분석하기 위해 `PROC_NAME`, `ERROR_CODE`, `ERROR_MSG`, `ERROR_STACK`, `ESB_SEQ`를 기반으로 관련 인터페이스 정의서와 운영 매뉴얼을 자동 매칭하는 대시보드를 구현했습니다. Excel/PDF 문서 일부를 추출해 AI 분석 context로 구성하고, 오류별 원인 후보, 확인 순서, 수정 방향, 확인 SQL 예시를 제공하도록 설계했습니다. 또한 처리 상태와 운영 메모, 유사 오류 이력을 저장해 반복 오류 대응 시간을 줄이는 운영 개선 흐름을 구현했습니다.

## 면접 설명 포인트

- 실제 운영 DB에는 연결하지 않고, 운영 테이블 구조를 재현한 mock 데이터로 시연했습니다.
- 문서 내용은 명령으로 실행하지 않고 분석 context로만 사용하도록 설계했습니다.
- API 키가 없거나 외부 AI 호출이 실패해도 mock 분석으로 fallback되어 시연 안정성을 확보했습니다.
- 현재 운영 이력은 인메모리 저장이며, 다음 단계에서 PostgreSQL 테이블로 확장할 수 있습니다.
- 실무에서는 `HIS_MAPPING_ERROR_LOG` 테이블, 인터페이스 정의서, 배포/서비스 매뉴얼을 연결해 장애 대응 시간을 줄이는 도구로 발전시킬 수 있습니다.

## 시연 순서

1. 오류 목록에서 `H31_ACPPEOCE_TO_ARROPCALNT` 또는 `H29_ACPPEICE_TO_ARRIPCALNT` 선택
2. 상세 영역에서 `ERROR_MSG`, 대상 테이블/컬럼, 발생 라인 확인
3. 관련 문서 카드와 snippet 확인
4. `문서 기반 분석 실행` 클릭
5. 원인 후보, 확인 순서, 수정 방향 확인
6. 처리 상태를 `확인중` 또는 `해결`로 변경
7. 운영 메모 입력 후 저장
8. 유사 오류 처리 이력 확인
